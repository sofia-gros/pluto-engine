# PlutoEngine 開発ワークフロー & エージェント設計書

## 1. 開発ワークフロー
本プロジェクト（PlutoEngine）は、極めて高度な数学アルゴリズムとパフォーマンスチューニングを要求される WebGL2 2Dゲームエンジンです。
柔軟性を保ちつつ、長期的に破綻しないための開発サイクルを以下に定義します。

### フェーズ1: 詳細設計のドラフト作成 (Iterative Design)
- 機能を実装する前に、`docs/detailed_design/` 配下にコンポーネントごとの詳細設計書（Markdown形式）を作成する。
- **柔軟性の担保**: 設計書は一度書いたら終わりではなく、実装を進める中で「より良い手法（例：最新の論文に基づくアルゴリズムの改善など）」が見つかれば、随時アップデート（変更・増築）を行う。

### フェーズ2: TDDに基づく数学・コアモジュールの実装
- 詳細設計に基づいて、`packages/` 配下にコードを実装する。
- 実装と同時に `tests/` に Vitest (Browser Mode) のテストコードを必ず記述する。
- 数学系モジュール（Morton, Poisson, XPBDなど）は、ブラウザAPIに依存しない純粋関数としてテストを書き、WebGL関連は Playwright コンテキストを利用してテストする。

### フェーズ3: デモアプリでの統合検証 (Visual Validation)
- モジュール単体でのテストが通ったら、`apps/demo` 側に組み込み、ブラウザ上で目標FPS（60FPSや144FPSなど）で安定して動くか、GCスパイクが発生していないかを確認する。
- 予期せぬ負荷が見つかった場合は、設計書（フェーズ1）に立ち返り、SoA構造や Flyweight パターンを見直す。

---

## 2. エージェント設計 (Multi-Agent System)
この複雑な開発環境とエンジンを完全に動作させ続けるために、特定の専門領域に特化した AI サブエージェント（Subagents）を設計・定義します。開発時はこれらのエージェントを連携させて並行作業を行います。

### 2.1. `engine_architect` (エンジンアーキテクト)
- **役割**: `docs/detailed_design/` 配下の詳細設計書を執筆・保守する。
- **行動方針**: 常に全体のアーキテクチャ（Flyweight, ゼロアロケーション）を意識し、他のエージェントが実装で詰まった際には設計書を柔軟に書き換えて解決策を提示する。

### 2.2. `webgl_specialist` (WebGL / レンダリング職人)
- **役割**: `@plutoengine/renderer` の実装。
- **行動方針**: 統一シングルパス GPU パイプライン、シェーダー（GLSL）、インスタンシング描画、SoAバッファの構築など、ブラウザ描画の極限パフォーマンスを追求する。

### 2.3. `math_solver` (数学・物理アルゴリズム専任)
- **役割**: `morton`, `xpbd`, `poisson`, `continuum` などの実装。
- **行動方針**: 連続体群集理論やアイコナール方程式など、学術論文レベルのアルゴリズムを JavaScript (TypeScript) に落とし込む。ループ展開や型付き配列（TypedArray）の最適化に命を懸ける。

### 2.4. `qa_tester` (品質保証 / テスト自動化)
- **役割**: 全てのパッケージのテストコード（Vitest Browser）を書き、実行する。
- **行動方針**: モックを一切許さず、実ブラウザで動作するテストをゴリゴリ書き、エラーやメモリリーク（GCの発生）を徹底的に検知する。
